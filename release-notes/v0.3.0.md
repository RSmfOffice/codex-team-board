# v0.3.0

发布日期：2026-11-07

## WebUI 集群控制

- 可从项目下拉框直接创建自动集群目标。
- 支持 `auto` 和 `supervised` 自治模式。
- Active/Planning 目标可暂停或取消，Paused 目标可恢复或取消。
- 恢复目标会同步确保 `teamd` 运行。
- 取消通过目标 `failed` 状态落板，原因写入 `last_error`，不删除任务和 Git
  worktree。

对应 API：

- `POST /api/clusters`：创建目标并返回 `{goal, daemon}`。
- `POST /api/clusters/control`：接受 `pause`、`resume`、`cancel`，返回
  `{goal, daemon}`。

## 健康摘要与 attention

`/api/board` 新增 `cluster_summary`，并提供每个目标的 `health`、
`next_action` 和 `attention_task_count`。

- `critical`：failed 目标、blocked 任务或认领等待至少 300 秒的 ready 任务。
- `warning`：paused 目标、review 任务或认领等待 60–299 秒的 ready 任务。
- `active`：存在启动中/运行中的 Agent job 或 running 任务。
- `planning`：目标仍在规划。
- `healthy`：其余情况。

`attention_count` 统计 blocked、review、认领等待至少 300 秒的任务，以及
paused/failed 目标，表示待处理信号数量而非去重目标数。60–299 秒等待只标为
warning，不单独增加 `attention_count`。

## 轮询与渲染

- 项目列表只在首次加载、归档状态或归档筛选变化时请求。
- 常规轮询只请求 `/api/board`，默认间隔 2 秒。
- 页面隐藏时停止轮询并取消在途请求，恢复可见时立即刷新。
- 失败重试采用 2、4、8、16、30 秒指数退避。
- 内容签名未变化时跳过重复渲染，避免动态 claim 年龄和 `generated_at`
  触发无效重绘。

## API 示例

```powershell
$base = "http://127.0.0.1:8765"
$projectId = (Invoke-RestMethod "$base/api/board").projects[0].project_id

$created = Invoke-RestMethod `
  -Uri "$base/api/clusters" `
  -Method Post `
  -ContentType "application/json" `
  -Body (@{
    project_id = $projectId
    objective = "完成发版前验证"
    autonomy = "auto"
  } | ConvertTo-Json)

Invoke-RestMethod `
  -Uri "$base/api/clusters/control" `
  -Method Post `
  -ContentType "application/json" `
  -Body (@{
    goal_id = $created.goal.goal_id
    action = "pause"
  } | ConvertTo-Json)
```

## 升级到 0.3.0

1. 完成当前运行中的任务，或先按需备份
   `%LOCALAPPDATA%\CodexTeam\team.sqlite`。数据库 schema 在本版本没有变化。
2. 完全退出 Codex，并停止旧的 Web 看板进程。
3. 更新仓库后重新运行安装器：

   ```powershell
   Set-Location "D:\path\to\codex-team-board"
   git pull --ff-only
   powershell.exe -NoProfile -ExecutionPolicy Bypass `
     -File .\scripts\install.ps1
   ```

4. 重新打开 Codex，并检查版本：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8765/api/health
   ```

预期 `version` 为 `0.3.0`。如果继续使用上下文插件联动，安装时追加
`-ContextMeterRoot "D:\path\to\codex-context-meter"`。

## 发布前 Debug 修复

- completed/failed 目标不能再被 resume；同一项目不能恢复出第二个 active goal。
- daemon 启动失败时，新建目标会自动标记 failed 并保留错误原因。
- 依赖尚未完成的 ready 任务不再误报“等待认领”。
- claim 等待从 normal 升为 warning/critical 时会触发必要重绘。
- `/favicon.ico` 返回 204，消除浏览器控制台 404。
