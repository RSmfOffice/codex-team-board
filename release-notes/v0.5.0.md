# v0.5.0

发布日期：2026-11-08

## 上下文与缓存架构

- 重构为“Lead 连续、Subagent fresh”：
  - Lead 在同一 project/workstream 内可自动恢复 thread。
  - Explorer、Reviewer、Worker 的 `auto` 模式默认新建 thread。
  - 任意角色可显式设置 `continuity_mode=reuse`。
- 新增上下文比例阈值
  `CODEX_TEAM_AGENT_REUSE_CONTEXT_RATIO`，默认 `0.85`。
- Stable Developer Prompt 改为角色 Contract 在前、项目/workstream 在后。
- Worker Assignment 改为通用规则在前、动态 Goal/Task/checkpoint 在后。
- 每个可复用 Agent thread 持久记录 context profile；旧 profile、缺失 profile
  或显式 `continuity_mode=reuse` 不兼容时都强制 fresh。

## 持久 Checkpoint

- `cluster_goals` 新增 `checkpoint_summary` 与 `checkpoint_updated_at`。
- 新增 MCP `team_goal_set_checkpoint`。
- 新增 CLI：

```powershell
.\scripts\team.ps1 cluster checkpoint <goal-id> --summary-file checkpoint.md
```

- fresh Worker 会收到同 workstream 最近 checkpoint 的截断摘要。
- 已归档 goal 的 checkpoint 仍参与同 workstream 继承；归档只用于整理页面，
  不切断 Agent 可恢复的历史。
- checkpoint 只保留决策、完成项、测试、风险、已否决方案和下一步，不保存原始
  日志或完整 transcript。

## Lead Board 摘要

- Lead 每轮只接收：
  - 状态计数；
  - 全部活动任务；
  - 最近 8 个完成任务的浓缩摘要；
  - 省略历史数量。
- 完整任务和事件通过 `team_get_task` / `team_get_task_events` 按需读取。
- 减少每轮重复注入完整历史导致的 context rot、token 成本和缓存前缀变化。

## Usage 与成本账本

- App Server job 使用本 job final `total` 与 thread baseline 的差值记录成本，
  不再只记录最后一次模型调用的 `last`。
- 取消、超时和中断前会 best-effort 读取 JSONL 中已有 token usage，避免真实
  成本丢失。
- `usage_missing_fields` 区分显式 0、字段缺失和完全无 usage 证据；Dashboard
  对未知字段显示 null，不伪造零成本。
- partial/unknown baseline 的成功 thread 会标记 failed/needs_reset，禁止进入
  复用池。

## 数据库

- schema 升级到 15。
- 迁移只新增列，不删除已有 goals、tasks、jobs、events 或 Agent thread。
- `TeamService` 启动时执行实际迁移；`/api/health` 的 `schema_version` 来自
  不可回退的 `schema_migrations` 账本，并兼容 SQLite `PRAGMA user_version`。
  即使旧版 MCP 进程仍短暂运行，已迁移版本也不会被误报为旧值。

## 升级

1. 暂停或完成运行中的团队任务。
2. 停止旧 `teamd` 和看板。
3. 更新并重新运行安装器。
4. 重启 daemon；首次启动自动迁移 schema 15。
5. 在 `/api/health` 确认版本为 `0.5.0`、schema 为 `15`。
