# Codex Team Board v0.5.0

发布日期：2026-11-10

v0.5.0 是稳定缓存前缀、Native Agent 监控和 Dashboard 扩容版本，schema 从 12
升级到 20。

## 高缓存命中与稳定前缀

- 默认 MCP 工具面切换为固定 schema 的 `core-v1`：
  `team_read` / `team_write` operation dispatcher。
- Agent cache profile 绑定角色 Prompt、项目 AGENTS、工具 schema、access mode、
  Prompt Contract、workflow epoch、schema 和运行时身份。
- Explorer/Reviewer 仅在完整兼容的 profile 下复用；Worker 默认 fresh。
- 旧 profile、缺失 context/window 或 partial usage baseline 会被隔离，不再污染
  新任务缓存。
- `workflow_epoch` 当前为 `workflow-v4`；Goal、Task、Job 绑定同一架构 cohort。

## Native Agent Threads

- 统一 `cluster_agents` Thread Registry，区分 `managed` 和 `native`。
- Dashboard/API 自动发现最近 Codex subagent sessions，按项目 cwd 幂等登记。
- `subagent_history_start_ordinal` 隔离父 Thread 历史。
- 解析 `token_usage_record` / `token_count`，显示真实 context、cached、
  uncached、cache rate、model window 和 turn 数。
- 无 usage 证据显示 `—`，显式零值仍显示 `0`。
- 已登记 Native Thread 超出发现窗口后仍可刷新 usage。
- `agent archive-stale` 可 dry-run/apply 归档 failed、superseded 与历史 profile
  managed Thread；默认诊断隐藏，审计事件、job 和 session 保留。

## 调度与可靠性

- 每个 Goal 独立运行 Lead 和最多 3 个 Worker。
- `teamd` tick 固定为
  `settle/recover/control/prepare/dispatch/health/publish`。
- 新增 durable attempt ledger、worktree intent 恢复、claim/archive 原子性和
  Review commit 门禁。
- 恢复失效依赖、停滞 Goal、过期 lease、App Server generation 和中断 usage。
- 项目归档同步只恢复 `archived_project`，不会误恢复独立清理的
  `archived_stale` Agent。

## Dashboard

- 新增 `/api/summary`、tasks/goals/agents/attempts/events 分区 API。
- `/api/board` 保持兼容，并支持 revision、弱 ETag、`304` 和 cursor 分页。
- WebUI 每 2 秒先读取 summary；revision 未变化时不下载完整 board。
- 任务详情按 task 读取事件，不再依赖全局最新 500 条。
- 写接口要求 loopback Host、same-origin Origin 和 JSON。
- 修复 canonical 配置缺失、归档竞争、非法状态迁移和脱敏遗漏。

## 升级

1. 暂停或完成运行中的 Goal 和 Task。
2. 停止旧 `teamd` 和 Dashboard。
3. 更新仓库并重新运行安装器。
4. 重启 daemon，首次启动自动迁移到 schema 20。
5. 检查 `/api/health` 的 `version=0.5.0`、`schema_version=20`。
6. 按需执行 `cluster migrate-workflow`；存在未完成任务时先写 checkpoint。
