# v0.4.0

发布日期：2026-11-07

## 多集群容量与公平调度

- 全局 Jobs 容量默认 4，统计所有项目中 `starting`/`running` 的 Lead 和 Worker。
- 每 goal Worker 容量默认 3；Lead 不占每 goal Worker 配额，但占全局 Jobs 槽位。
- 调度器优先选择最久未启动 job 的 goal，再参考活动 job 数；goal 内按任务
  priority 和创建时间派发。
- 全局容量已满且存在可派发 Worker 时记录 `fairness_deferred`。事件包含
  `reason`、`ready_tasks` 和 `capacity`，相同 goal/原因最多每 60 秒记录一次。
- 仍有未完成依赖的 ready 任务使用 `dependency_wait` 队列原因；WebUI 显示
  “等待依赖完成”，等待时长以“当前等待”展示。

## 集群生命周期

- 新增 `team_cluster_ensure` 和 `cluster ensure`，在首次编辑或创建 worktree 前
  幂等复用项目现有的 `planning`/`active`/`paused` 目标。
- `cluster ensure` 返回 `created`、`reused` 和 `requires_resume`；paused 目标
  只提示恢复，不会自动恢复。`team_cluster_start` 继续用于明确新建目标。
- 新增集群目标归档与恢复。只有已结束且无活动 job 的 `completed`/`failed` 目标
  可以归档；归档为软删除，记录、任务、事件和 worktree 均保留。
- WebUI 的“显示已归档”筛选同时覆盖项目、任务和集群目标；归档集群目标可在
  看板中恢复。

## 长任务与心跳诊断

- Worker 默认运行 2 小时后超时，Lead 默认运行 45 分钟后超时。超时会终止对应
  process tree，并进入已有的 Worker/Lead 重试与 blocked 处理流程。
- Worker 的 `claimed`、`heartbeat`、`progress` 活动超过 5 分钟记录 warning；
  超过 15 分钟记录 critical。心跳告警只用于诊断，不会直接终止 job。
- WebUI 新增 `JOBS`、`QUEUED`、`HB OVERDUE`，以及每 goal 的队列原因、活动 job、
  heartbeat 年龄和当前等待时长。

## 配置

| 环境变量 | 默认值 | 输入范围 | 有效调度值 |
| --- | ---: | ---: | ---: |
| `CODEX_TEAM_CLUSTER_MAX_JOBS` | `4` | `1..86400` | 最多 `16` |
| `CODEX_TEAM_CLUSTER_MAX_WORKERS` | `3` | `1..86400` | 最多 `8` |
| `CODEX_TEAM_WORKER_TIMEOUT_SECONDS` | `7200` | `1..86400` | 输入值 |
| `CODEX_TEAM_LEAD_TIMEOUT_SECONDS` | `2700` | `1..86400` | 输入值 |
| `CODEX_TEAM_HEARTBEAT_WARNING_SECONDS` | `300` | `1..86400` | 输入值 |
| `CODEX_TEAM_HEARTBEAT_CRITICAL_SECONDS` | `900` | `1..86400` | 不低于 warning |

环境变量在 `teamd`、管理命令和看板进程启动时读取。修改后应先停止 daemon，
再在目标环境中设置变量并通过 `scripts/ensure-cluster-daemon.ps1` 重启；
看板也应重启，避免显示的容量与实际调度不一致。README 包含完整命令。
容量变量输入可到 `86400`，但调度的有效上限是全局 Jobs `16`、每 goal Workers
`8`。若 critical 小于 warning，有效 critical 会被提升到 warning。

## 升级影响

- 数据库 schema 未变化，不需要额外迁移。
- 升级后应完全退出 Codex，停止旧的 Web 看板和 `teamd`，更新仓库并重新运行
  `scripts/install.ps1`。
- 现有的单项目目标继续可用。需要并行多个 goal 时，必须分别位于不同项目；
  同一项目仍只允许一个 `planning`/`active` goal。
- 非平凡开发应迁移到幂等的 `cluster ensure`；若返回 `requires_resume: true`，
  需由用户显式恢复 paused 目标，不得依赖自动恢复。
- 默认超时为 Worker 2 小时、Lead 45 分钟。若现有作业依赖更短超时，请显式设置
  上述环境变量。
- 未配置两个 heartbeat 阈值时继续使用 300 秒 warning、900 秒 critical。若
  critical 配置小于 warning，它不会产生更早的 critical 告警。
- 环境变量不会自动写入正在运行的 daemon；必须在重启 `teamd` 前设置。
- `teamd` 与看板必须使用相同的容量环境变量，否则看板的容量和排队判断会与
  实际调度不一致。
- `read` 任务 Worker 和 Review Worker 在 `read-only` 沙箱中运行；只有 `write`
  Worker 和 `auto` 模式 Lead 使用 `danger-full-access`。

## 已知边界

- 公平调度是动态轮转，不提供每个 goal 的最小槽位保证；全局 Jobs 容量始终优先。
- 超时按 job 启动时间计算，收到 heartbeat 或 progress 不会延长总运行时长。
- 心跳 warning/critical 只产生诊断事件，不会自动杀死进程；实际回收依赖 job
  timeout、进程退出或 daemon 的租约恢复逻辑。
- 多个集群必须共享同一个 `CODEX_TEAM_HOME` 数据库和目标 `teamd`，否则全局容量
  与公平顺序无法跨数据库生效。
- `supervised` 模式仍在 Review 阶段暂停，等待人工验收；多集群调度不会绕过该规则。
