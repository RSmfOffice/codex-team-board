# v0.4.2

发布日期：2026-11-08

## 默认 Agent Thread 复用

- Agent 集群任务默认使用私有 `app_server` runtime。
- 新上下文通过 `thread/start` 创建，连续 workstream 通过 `thread/resume`
  复用持久 thread，每轮任务通过 `turn/start` 下发。
- 未设置 `CODEX_TEAM_AGENT_RUNTIME` 或设置为空时均使用 `app_server`。
- 需要完全关闭持久 thread 时，显式设置
  `CODEX_TEAM_AGENT_RUNTIME=exec`。
- 默认 write Worker 的安全规则不变：`auto` 仍 fresh，只有显式
  `continuity_mode=reuse` 才复用 thread。

## 缓存依据

8 组交叉顺序微探针、共 32 个模型 turn 的结果：

- `app_server` 第二轮平均 cache hit：`98.57%`
- `exec` 第二轮平均 cache hit：`98.00%`
- 配对平均差：`+0.58pp`
- Bootstrap 95% CI：`[+0.31pp, +0.89pp]`
- 正向配对：`8/8`

缓存优势限定在同一 thread 的后续 turn；两轮合并命中率不代表所有新任务都更高。

## 看板

- `/api/health` 和 `/api/board` 返回当前 daemon runtime、thread reuse 状态、
  daemon 在线状态和配置漂移状态。
- 顶部新增 `RUNTIME` 指标。
- 活动任务显示 `thread reuse` 或 `fresh exec` badge。
- Agent Threads 诊断区继续展示 thread、workstream、context、cache 和重置入口。
- 推送 `v0.4.2` tag 后，Windows GitHub Actions 自动复用同一套测试和打包脚本，
  创建 Release 并上传 ZIP 与 SHA256。

## 工程修复

- `pyproject.toml`、`src/codex_team/__init__.py`、健康接口和发布包版本统一为
  `0.4.2`。
- 默认 runtime、显式 exec 回退、health/board runtime 契约和 UI smoke 均有回归测试。

## 升级

1. 完成或暂停当前活动 Agent job。
2. 停止旧 `teamd` 和旧看板。
3. 更新仓库并重新运行 `scripts/install.ps1`。
4. 使用 `teamctl daemon restart --if-idle` 或
   `scripts/ensure-cluster-daemon.ps1` 启动新 daemon。
5. 检查 `/api/health` 中 `cluster_runtime.runtime` 为 `app_server`。

如遇 App Server 兼容问题，可设置 `CODEX_TEAM_AGENT_RUNTIME=exec` 并重启
daemon，恢复独立进程模式。
